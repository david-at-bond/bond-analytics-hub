Snowflake MCP Setup Guide

Connect Claude Code to Bond's Snowflake data warehouse. Read-only access — you can query any table, but cannot modify, insert, or delete anything.

What this gives you

Once set up, you can ask Claude natural-language questions about Bond data and it will write and run the SQL for you — directly against Snowflake. Examples:

"How many active organizations do we have?"
"Show me the last 10 Salesforce opportunities and their ARR"
"What does the actions table look like for org 1234?"

All queries run as your Snowflake user with a read-only role. You cannot modify data — the config blocks every write operation at the tool level.

★
Admin setup — Brett does this once per new user
Run this SQL in Snowflake as ACCOUNTADMIN or SYSADMIN. Skip if the user already exists.
Step 1 — Create the shared read-only role (one time, ever)
-- Run once to create the shared read-only role
USE ROLE SYSADMIN;

CREATE ROLE IF NOT EXISTS BOND_READONLY;

-- Grant warehouse access
GRANT USAGE ON WAREHOUSE DEV TO ROLE BOND_READONLY;

-- Grant read access to the ANALYTICS database
GRANT USAGE ON DATABASE ANALYTICS TO ROLE BOND_READONLY;
GRANT USAGE ON ALL SCHEMAS IN DATABASE ANALYTICS TO ROLE BOND_READONLY;
GRANT SELECT ON ALL TABLES IN DATABASE ANALYTICS TO ROLE BOND_READONLY;
GRANT SELECT ON ALL VIEWS IN DATABASE ANALYTICS TO ROLE BOND_READONLY;
GRANT SELECT ON FUTURE TABLES IN DATABASE ANALYTICS TO ROLE BOND_READONLY;
GRANT SELECT ON FUTURE VIEWS IN DATABASE ANALYTICS TO ROLE BOND_READONLY;
Step 2 — Create the user and assign the role
ℹ No password — authentication is SSH key-based. The user will generate their key pair and send you their public key before you run Step 3. 
-- Replace FIRSTNAME_LASTNAME with the actual username (ALL_CAPS)
CREATE USER IF NOT EXISTS FIRSTNAME_LASTNAME
  DEFAULT_ROLE = BOND_READONLY
  DEFAULT_WAREHOUSE = DEV
  DEFAULT_NAMESPACE = ANALYTICS;

GRANT ROLE BOND_READONLY TO USER FIRSTNAME_LASTNAME;
Step 3 — Register the user's public key

Wait for the user to complete Step 2 below and send you their public key. Then run this — paste their key content (the base64 block, no header/footer lines) as the value:

-- Paste the user's public key content between the quotes
-- It's the lines between -----BEGIN PUBLIC KEY----- and -----END PUBLIC KEY-----
-- Remove those header/footer lines; keep only the base64 content
ALTER USER FIRSTNAME_LASTNAME SET
  RSA_PUBLIC_KEY='MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...';
✓ Once registered, the user's private key authenticates them — no password is ever stored or shared. To revoke access, run ALTER USER FIRSTNAME_LASTNAME UNSET RSA_PUBLIC_KEY;

1
Install uv — the Python runner
The Snowflake MCP server runs via Python. uv manages this automatically — you don't need Python installed.

Open PowerShell (search "PowerShell" in Start) and run:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Close and reopen PowerShell when it finishes. Verify with:

uvx --version
✓You should see a version number like uvx 0.11.x. If you see "command not found", close and reopen PowerShell.

Open Terminal and run:

curl -LsSf https://astral.sh/uv/install.sh | sh

Close and reopen Terminal when it finishes. Verify with:

uvx --version
✓You should see a version number like uvx 0.11.x.

3
Create your Snowflake connection file
Points to your private key. No password stored anywhere.

In PowerShell:

New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.snowflake"
notepad "$env:USERPROFILE\.snowflake\connections.toml"

Paste the following — replace YOUR_USERNAME and the key path with your actual Windows username:

[default]
account          = "VYQVYJM-BOND_WAREHOUSE"
user             = "YOUR_USERNAME"                            # e.g. LOGAN_CASHMAN
private_key_path = "C:/Users/YourWindowsName/.snowflake/snowflake_key.p8"
role             = "BOND_READONLY"
warehouse        = "DEV"
database         = "ANALYTICS"
ℹ To find your Windows username, run echo $env:USERNAME in PowerShell. Use forward slashes in the path, not backslashes.

In Terminal:

open -e ~/.snowflake/connections.toml

Paste the following — replace YOUR_USERNAME:

[default]
account          = "VYQVYJM-BOND_WAREHOUSE"
user             = "YOUR_USERNAME"          # e.g. LOGAN_CASHMAN
private_key_path = "~/.snowflake/snowflake_key.p8"
role             = "BOND_READONLY"
warehouse        = "DEV"
database         = "ANALYTICS"
4
Create the MCP permissions config
Locks Claude to read-only SQL — SELECT, SHOW, DESCRIBE, USE only. All writes blocked.
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.claude"
notepad "$env:USERPROFILE\.claude\snowflake-config.yaml"
mkdir -p ~/.claude && open -e ~/.claude/snowflake-config.yaml

Paste this content exactly — do not change it:

other_services:
  object_manager: true
  query_manager:  true
  semantic_manager: false

sql_statement_permissions:
  - Select:        True
  - Describe:      True
  - Use:           True
  - Show:          True
  - Alter:         False
  - Command:       False
  - Create:        False
  - Delete:        False
  - Drop:          False
  - Insert:        False
  - Merge:         False
  - Update:        False
  - TruncateTable: False
  - Copy:          False
  - Transaction:   False
  - Unknown:       False
5
Register the MCP server with Claude Code
Run once. This adds Snowflake to your Claude Code config permanently.

In PowerShell:

claude mcp add snowflake `
  --transport stdio `
  -- "$env:USERPROFILE\.local\bin\uvx.exe" snowflake-labs-mcp `
  --service-config-file "$env:USERPROFILE\.claude\snowflake-config.yaml" `
  --connection-name default

In Terminal:

claude mcp add snowflake \
  --transport stdio \
  -- uvx snowflake-labs-mcp \
  --service-config-file ~/.claude/snowflake-config.yaml \
  --connection-name default
ℹ This writes to your user-level Claude config (~/.claude.json). It applies to every Claude Code session, not just this project.

Troubleshooting
SymptomFix
✗ Failed to connect in mcp list Check connections.toml — confirm private_key_path points to where you generated the key (e.g. C:/Users/YourName/.snowflake/snowflake_key.p8). Username must be all caps (e.g. LOGAN_CASHMAN).
uvx: command not found Close and reopen your terminal after installing uv. On Mac, you may need to run source ~/.bashrc or source ~/.zshrc
Permission denied when running a query Your Snowflake user may not have the BOND_READONLY role yet — ask Brett to run Step 2 of the admin setup
Claude says it can't write data This is correct. The config blocks all writes. If you need write access for a specific task, ask Brett.
MCP registered but shows ! Needs authentication This is a different error — your connections.toml file may not exist or may be in the wrong location. Verify the path exactly.
